# 错误经验错题本

用这份 Skill 复用已经验证的失败经验，避免同类问题反复试错。公开仓库只提供 [空白模板](references/error-notebook.md)；个人错题默认保存在 `~/.codex/error-notebook-data/error-notebook.md`，也可以通过 `CODEX_ERROR_NOTEBOOK_PATH` 指定其他私有路径。

首次安装时运行 `python scripts/init_private_notebook.py`。初始化只在私有文件不存在时复制空白模板，绝不覆盖已有数据。检索、校验和复核脚本会优先使用私有文件；尚未初始化时才读取公开模板。

## 开始任务时检索

1. 从当前任务提取 2～6 个有区分度的关键词，优先包括技术栈、操作系统、工具名、错误码、异常类型或原始错误短语。
2. 运行 `python scripts/search_notebook.py "关键词1" "准确错误短语"`。路径以本 Skill 目录为基准；如果当前环境只能从别处执行，传入 `--notebook` 指定文件。
3. 只使用输出中的使用规则、分类索引和匹配经验。没有匹配项时继续任务，不为满足形式要求读取无关内容。
4. 只有无法判断分类、关键词检索不足，或正在整理、去重错题本时，才读取全文。
5. 检索结果标记为“待复核”“已到期”“已失效”或“已替代”时，只把它当作调查线索；先在当前环境重新验证，再决定是否采用并更新状态。

如果脚本无法运行，可对错题本使用等价的字面量搜索；不要因此阻断主任务。

## 失败后再次检索

遇到命令失败、构建失败、工具缺失、权限限制、环境差异、编码问题、依赖冲突、错误操作或用户纠正时：

1. 保留准确错误文本、相关版本、执行入口和可观察结果。
2. 使用准确错误短语加关键技术词再次运行检索。
3. 将命中的经验作为调查线索，仍需用当前代码、配置、日志或实际命令验证其适用性；旧经验不是当前事实的替代品。
4. 优先定位根因，避免通过吞异常、关闭校验、硬编码特例或无限重试掩盖问题。

## 写入门槛

只有同时满足以下条件，才把本次经验写入错题本：

- 根因已由日志、代码、命令结果或可重复现象确认；
- 解决方式已实际执行，并由与问题直接相关的验证证明有效；
- 经验可以跨项目复用，而不是单个项目的业务约定；
- 内容不包含密码、Token、Cookie、私钥、完整连接串、个人隐私或生产业务数据；
- 已检索相同或相近条目，确认应新增还是最小补充现有条目。

一次性外部状态、无法复现的偶发现象或仍在推测中的原因只在当前任务结果中说明，不写成强制规则。项目专属约定应写入项目自己的 `AGENTS.md`、README 或其他项目文档。

## 记录或更新

同一触发条件和同一根因优先更新原条目；同一表象但根因不同，可在对应分类下新增区分明确的标题。不要重排或重写无关内容。

写入前确认脚本解析到的是私有数据文件；如果当前仍在使用仓库内的公开模板，先运行 `python scripts/init_private_notebook.py`，禁止把个人错题直接写入或提交到公开仓库。

每条经验使用以下结构：

```markdown
## 分类

### 可检索的具体标题

- 状态：有效
- 复核周期：90天
- 适用范围：明确的软件版本、操作系统、工具入口和触发边界。
- 最后验证：2026-09-06
- 下次复核：2026-12-05
- 验证证据：记录实际执行的命令、日志、代码位置或官方资料及其可观察结果。
- 替代条目：无
- 适用条件或错误特征：包含准确错误、环境和触发条件。
- 根因判断：说明经过证据确认的根本原因。
- 正确处理：给出已验证的处理动作和必要边界。
- 禁止做法：指出会掩盖问题、扩大风险或已证实无效的做法。
```

生命周期字段遵循以下规则：

- `状态` 只能是 `有效`、`待复核`、`已失效` 或 `已替代`。
- `复核周期` 按变化风险选择：工具、API、框架和云服务使用 `90天`；操作系统、构建和部署环境使用 `180天`；Git、安全边界和稳定操作原则使用 `365天`。
- `有效` 条目必须填写 ISO 日期格式的 `最后验证`、`下次复核` 和可复查的 `验证证据`。不得用创建日期冒充验证日期。
- 迁移前没有可靠日期或证据的存量条目统一标为 `待复核`，允许使用 `未记录（迁移存量）`、`首次命中时` 和 `待复核后补充`；不得据此宣称规则当前有效。
- `已失效` 和 `已替代` 条目的 `复核周期`、`下次复核` 填写 `不适用`，但仍须记录本次确认日期和证据；`已替代` 还必须在 `替代条目` 中使用 `分类 / 标题` 填写同一错题本内的新条目。
- 失效和替代条目保留历史，不直接删除。
- 每次命中都优先做现场复核；复核成功后更新验证日期、证据和下次复核日期，复核失败则改为 `已失效` 或 `已替代`。

更新后运行：

```text
python scripts/validate_notebook.py
```

每月至少运行一次到期扫描；只复核到期条目，不机械重验全文：

```text
python scripts/review_notebook.py
```

需要把到期或待复核条目作为自动化检查失败处理时，增加 `--fail-on-action`。扫描只报告状态，不会自动修改或删除条目。

重新读取新增或修改的段落，确认 UTF-8、内容完整、没有重复或敏感信息。若 Skill 所在位置只读，明确说明尚未保存，并给出可直接合并的条目；不要声称已更新。

## 私有数据与公开代码

可以把全局 Skill 安装路径通过 Windows Junction 指向 Git 仓库中的 `error-notebook` 目录；安装或修复链接时运行 `scripts/install_windows_junction.ps1`。Junction 只共享 Skill 代码，真实错题仍位于仓库之外的私有数据路径。

- 更新个人错题后，验证私有文件已经保存，但不要把它复制、暂存或推送到公开仓库。
- Git 仓库只提交 `SKILL.md`、脚本、公开空白模板和不含个人数据的说明。
- 提交前运行 `python scripts/validate_public_repo.py`，确认公开模板仍为空且已跟踪文件未出现高风险凭据或个人绝对路径。
- 只有用户明确要求提交或推送时，才执行对应 Git 操作；私有错题更新与 GitHub 同步相互独立。
- Junction 安装脚本生成的时间戳备份仅用于迁移回滚，不是后续维护入口。

## 输出边界

- 把“已确认根因”“已验证修复”“仅供调查的线索”明确区分。
- 不因命中历史经验就跳过当前环境验证。
- 不把一份庞大的通用调试教程塞入错题本；这里只保存非显然、可复用、已证实的经验。
- 不擅自修改调用方项目、全局规则或远端仓库；这些操作仍遵循当前任务的授权边界。
