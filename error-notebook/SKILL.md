# 错误经验错题本

复用非显然、可跨项目复用且已验证的失败经验。历史条目是调查线索，采用前结合当前代码、配置、日志或命令确认适用范围。

## 执行入口与数据位置

脚本需要 Node.js 18 或更高版本，无第三方 npm 依赖。以下命令从本 Skill 目录执行；在调用方项目中执行时，把 `scripts/...` 替换为本 Skill 下脚本的绝对路径并加引号。`--notebook` 只选择数据文件，不能修正脚本路径。

个人错题默认保存在 `~/.error-notebook/error-notebook.md`，可用 `ERROR_NOTEBOOK_PATH` 覆盖；兼容旧变量 `CODEX_ERROR_NOTEBOOK_PATH` 和已有的旧版私有文件。首次默认检索、校验或扫描会从 [公开空白模板](references/error-notebook.md) 初始化私有文件，不覆盖已有数据。仅在安装、迁移或定位数据路径时读取 [安装与私有数据](references/maintenance.md)。

## 开始任务时检索

1. 从当前任务提取 2～6 个有区分度的关键词，优先包括技术栈、操作系统、工具名、错误码、异常类型或原始错误短语。
2. 运行 `node scripts/search-notebook.mjs "关键词1" "准确错误短语"`。自选已有数据文件时追加 `--notebook "数据文件绝对路径"`。若检索词以 `--` 开头，将所有选项放在前面，再用 `--` 分隔，例如 `node scripts/search-notebook.mjs --max-results 3 -- "--ignore-scripts"`。
3. 默认只输出命中关键词数量最高的相关经验，最多 3 条。没有匹配项时继续任务；需要扩大候选范围、判断分类或检查结构时才增加 `--verbose`，输出较广泛的匹配、使用规则和完整分类索引，默认最多 8 条。可用 `--max-results` 调整数量。
4. 只有无法判断分类、关键词检索不足，或正在整理、去重错题本时，才读取全文。
5. 标记为“待复核”“已到期”“已失效”或“已替代”时，不直接套用处理动作；确认适用范围和当前证据后再采用。仅有检索命中不能刷新验证日期。

如果脚本无法运行，可对已确认的私有文件使用等价的字面量搜索；数据不可用时说明限制并继续主任务，不把执行失败当作“无匹配”。

## 失败后再次检索

遇到命令、构建、工具、权限、环境、编码、依赖问题或用户纠正时：

1. 保留准确错误文本、相关版本、执行入口和可观察结果。
2. 使用准确错误短语加关键技术词再次检索。
3. 用当前代码、配置、日志或实际命令确认命中经验的适用性。
4. 优先定位根因，避免通过吞异常、关闭校验、硬编码特例或无限重试掩盖问题。

## 写入门槛

只有同时满足以下条件，才把本次经验写入错题本：

- 根因已由日志、代码、命令结果或可重复现象确认。
- 解决方式已实际执行，并由与问题直接相关的验证证明有效。
- 经验可以跨项目复用，而不是单个项目的业务约定。
- 内容不包含密码、Token、Cookie、私钥、完整连接串、个人隐私或生产业务数据。
- 已检索相同或相近条目，确认应新增还是最小补充现有条目。

一次性外部状态、无法复现的偶发现象或仍在推测中的原因只在当前任务结果中说明。项目专属约定留在项目上下文中，不因本 Skill 自动修改项目文档。

## 记录或更新

满足写入门槛后，读取 [记录格式与生命周期](references/recording.md)。同一触发条件和同一根因优先更新原条目；同一表象但根因不同，可新增区分明确的标题，不重排无关内容。

写入前确认目标是仓库外的私有文件；默认路径可运行 `node scripts/init-private-notebook.mjs` 查看实际位置。若配置仍指向公开模板或公开仓库，按安装与私有数据说明纠正后再写入。公开模板只能保持为空。

更新后运行 `node scripts/validate-notebook.mjs`；使用自选文件时追加与本次编辑一致的 `--notebook` 路径。重新读取修改段落，确认 UTF-8、内容完整、无重复和敏感信息。若私有数据文件不可写，说明尚未保存并给出脱敏后的可合并条目；Skill 代码目录只读不代表私有数据不可写。

## 按需复核

整理错题本或检查到期经验时，运行 `node scripts/review-notebook.mjs`，再按需读取记录格式与生命周期。扫描只报告，不修改或删除条目；需要用退出码表示有待处理项时增加 `--fail-on-action`。可以建议每月扫描，但不因本 Skill 自动创建定时任务或全量复核。

无法验证、环境不匹配或暂时缺少权限，不等于经验失效。只有证据证明原适用范围内的处理方式不再成立，才标记为“已失效”；“已替代”还需指向已验证的替代条目。

## 输出与授权边界

- 区分“已确认根因”“已验证修复”“仅供调查的线索”，如实说明保存及校验结果。
- 不擅自修改调用方项目、全局规则或远端仓库；这些操作仍遵循当前任务的授权边界。
- 私有经验不复制、暂存或推送到公开仓库。仅在用户明确要求提交或推送时执行对应 Git 操作；公开代码提交前运行 `node scripts/validate-public-repo.mjs`。
